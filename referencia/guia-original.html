Modo Deus do Claude: o guia completo

Artigo da Anthropic: How we built our multi-agent research systemDocumentação: subagentes do Claude CodeDocumentação: comando /goal
Passo a passo
  1. 1Entenda a ideia. "Modo Deus" é o apelido que eu dei pra uma combinação, não existe um botão com esse nome nas configurações. A combinação é: o modelo mais caro (Opus, com esforço extra) só pensa, planeja e confere. Os modelos mais baratos (Haiku) executam o trabalho braçal. Tudo roda num loop de executa, verifica e corrige até cumprir um objetivo. Você ganha resultado melhor e gasta menos tokens, porque o modelo caro deixa de fazer tudo sozinho. É o mesmo padrão orquestrador e subagentes que a Anthropic descreve no artigo linkado acima.
  2. 2O que você precisa: o Claude Code instalado e uma pasta de projeto (pode ser uma pasta nova). Abra o terminal dentro dessa pasta. Os comandos e arquivos abaixo foram conferidos na documentação oficial do Claude Code. As peças são seis: estrutura de pastas, orquestrador, executor, configurações, regras no CLAUDE.md e um objetivo com /goal.
  3. 3Passo 1, a estrutura de pastas. Abra o Claude Code na pasta do projeto e cole o prompt abaixo pra ele criar tudo. Depois disso você vai ter exatamente a estrutura do vídeo: CLAUDE.md, a pasta .claude com agents, skills e settings.json, e a pasta memoria.
    Prompt
    Crie esta estrutura de pastas e arquivos vazios no meu projeto, sem mexer em nada que já exista:

meu-projeto/
├─ CLAUDE.md
├─ .claude/
│  ├─ agents/
│  │  ├─ orquestrador.md
│  │  └─ executor.md
│  ├─ skills/
│  └─ settings.json
└─ memoria/
   └─ plano.md

A raiz é a pasta onde estamos agora. Não crie a pasta "meu-projeto", só o que está dentro dela.
  4. 4Passo 2, o orquestrador. Esse é o agente que lidera: roda no Opus com esforço extra alto, planeja, delega e confere. Repare que ele não tem permissão pra delegar pra qualquer um, só pro executor (Agent(executor)). Peça pro Claude Code salvar o arquivo .claude/agents/orquestrador.md com este conteúdo. Se o seu Opus não tiver o nível xhigh (Extra alto), troque por high.
    Prompt
    Salve em .claude/agents/orquestrador.md exatamente este conteúdo:

---
name: orquestrador
description: Líder do projeto. Planeja, divide o trabalho, delega pros executores e confere cada entrega.
model: opus
effort: xhigh
tools: Agent(executor), Read, Write, Edit, Bash, Glob, Grep
---

Você é o orquestrador. Você pensa, planeja e confere. Você não faz o trabalho braçal.

Como trabalhar:
1. Antes de tudo, leia memoria/plano.md se ele tiver conteúdo.
2. Entenda o objetivo e escreva o plano em memoria/plano.md: etapas pequenas, cada uma com um critério de pronto que dê pra verificar.
3. Delegue cada etapa pro executor. Quando as etapas forem independentes, chame vários executores em paralelo. No pedido, diga o que fazer, em quais arquivos e como provar que ficou pronto.
4. Quando o executor devolver, confira de verdade: leia o arquivo, rode o teste. Nunca aceite "feito" sem evidência.
5. Se a verificação falhar, mande o executor corrigir passando o erro exato. Repita até passar.
6. A cada etapa concluída, atualize memoria/plano.md com o que foi feito e o que falta.
7. No fim, mostre as evidências na conversa (saída de comandos, testes), não só diga que terminou.
  5. 5Passo 3, o executor. É o trabalhador barato: roda no Haiku, faz só a etapa que recebeu e devolve a prova. Peça pro Claude Code salvar em .claude/agents/executor.md:
    Prompt
    Salve em .claude/agents/executor.md exatamente este conteúdo:

---
name: executor
description: Executa uma etapa específica passada pelo orquestrador e devolve evidência de que ficou pronta.
model: haiku
tools: Read, Write, Edit, Bash, Glob, Grep
maxTurns: 30
---

Você executa uma etapa que o orquestrador passou. Faça só isso, sem ampliar o escopo.

- Leia o que precisar antes de editar qualquer coisa.
- Ao terminar, devolva três coisas: os arquivos que mudaram, o comando de verificação que você rodou e a saída dele.
- Se travar, diga exatamente onde e por quê. Não invente resultado.
- Se tiver dúvida sobre o pedido, pergunte pro orquestrador em vez de adivinhar.
  6. 6Passo 4, as configurações. O settings.json faz três coisas: abre o Claude Code já como orquestrador, fixa o esforço em Extra alto e liga a auto-compactação em 40% da sessão (a variável CLAUDE_AUTOCOMPACT_PCT_OVERRIDE). Peça pro Claude Code salvar em .claude/settings.json:
    Prompt
    Salve em .claude/settings.json exatamente este conteúdo:

{
  "agent": "orquestrador",
  "effortLevel": "xhigh",
  "env": {
    "CLAUDE_AUTOCOMPACT_PCT_OVERRIDE": "40"
  }
}
  7. 7Passo 5, as regras do projeto e as skills que se aprimoram sozinhas. O CLAUDE.md é lido em toda sessão. Aqui entram a divisão de papéis, a memória e a regra que faz suas skills melhorarem a cada erro corrigido. Peça pro Claude Code salvar em CLAUDE.md:
    Prompt
    Salve em CLAUDE.md exatamente este conteúdo:

# Regras do projeto

## Quem faz o quê
- O orquestrador (Opus) lidera: planeja, delega e confere.
- O executor (Haiku) faz o trabalho braçal e devolve evidência.
- Trabalho braçal nunca fica no orquestrador.

## Plano e memória
- Toda tarefa grande começa com um plano em memoria/plano.md e termina com evidência de que funcionou.
- Decisões e estado ficam na pasta memoria/. Depois de uma compactação de contexto, releia memoria/plano.md antes de continuar.

## Skills que se aprimoram
- Quando uma skill em .claude/skills falhar, for corrigida por mim ou você descobrir um jeito melhor, atualize o SKILL.md dela no fim da tarefa.
- Acrescente a lição na seção "Lições aprendidas", suba a versão (v1 vira v2) e diga em uma linha o que mudou.
- Nunca reescreva a skill inteira. Só acrescente ou ajuste o trecho que falhou.
  8. 8Passo 6, crie sua primeira skill com o formato que se aprimora. Troque o nome e o passo a passo pelo que você faz de repetitivo. A seção Lições aprendidas começa vazia: é nela que o Claude vai escrevendo o que aprende. Peça pro Claude Code salvar em .claude/skills/nome-da-skill/SKILL.md:
    Prompt
    Crie a skill .claude/skills/nome-da-skill/SKILL.md com este modelo e preencha com a tarefa que eu vou te descrever:

---
name: nome-da-skill
description: Quando usar esta skill, em uma frase.
---

Versão: v1

# Passo a passo
1. (primeiro passo)
2. (segundo passo)
3. (como verificar que ficou certo)

# Lições aprendidas
(vazio por enquanto. O Claude acrescenta aqui a cada erro corrigido.)
  9. 9Passo 7, abra o Claude Code na pasta do projeto. Como o settings.json já aponta o agent orquestrador, ele abre sozinho como orquestrador. Se preferir abrir manualmente, use claude --agent orquestrador. Confira com /model (tem que estar no Opus) e /effort status (tem que estar em xhigh). Se quiser trocar o esforço na hora, é /effort seguido do nível: low, medium, high, xhigh ou max.
  10. 10Passo 8, o loop de verificação com um objetivo. É o /goal: você escreve a condição de pronto, e depois de cada turno um avaliador confere se ela foi cumprida. Se não foi, o Claude continua trabalhando com o motivo como guia. Escreva sempre três coisas: o estado final que dá pra medir, o comando que prova e um limite de turnos pra não rodar pra sempre. Atenção: o avaliador só julga o que apareceu na conversa, ele não roda comando nem abre arquivo. Por isso a condição pede pra mostrar a saída do teste na conversa. Exemplo:
    Prompt
    /goal Todos os testes passam (npm test sem nenhuma falha) e o resumo da entrega está em memoria/plano.md. Mostre a saída do npm test na conversa como prova. Pare depois de 20 turnos se não chegar lá.
  11. 11Pra conferir ou cancelar um objetivo: /goal sozinho mostra o status, e /goal clear remove. O objetivo vale só pra sessão atual.
  12. 12A auto-compactação em 40% e 60%. Quando a conversa enche, o Claude Code compacta o contexto. A variável CLAUDE_AUTOCOMPACT_PCT_OVERRIDE define em que porcentagem isso acontece: valores menores compactam mais cedo. Eu uso 40 no dia a dia (já está no settings.json do passo 4) e 60 nas tarefas maiores, que precisam de mais contexto vivo. Pra tarefa grande, mude o valor "40" pra "60" no settings.json e reinicie o Claude Code. Ela só serve pra compactar mais cedo que o padrão: valores acima do padrão do Claude Code são ignorados. É por isso que o orquestrador grava o plano em memoria/plano.md: depois de compactar, ele relê o plano e não perde o fio.
  13. 13O ganho de verdade e o custo. O modelo caro pensa pouco e decide muito, os baratos fazem o volume. No artigo da Anthropic, um sistema com Opus liderando subagentes bateu o Opus sozinho em 90,2% na avaliação interna deles. O mesmo artigo avisa que sistemas multiagente gastam bem mais tokens que uma conversa comum, cerca de 15 vezes, e por isso compensam em tarefas de valor alto. Moral: use o Modo Deus em trabalho grande, que tem várias partes e dá pra verificar. Pra pergunta simples ou ajuste pequeno, converse direto, sem orquestrar.
